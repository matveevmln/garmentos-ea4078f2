# GarmentOS — mobile-first visual lab

## Что будет сделано

- Перестроить текущую навигацию вокруг production-first сценария: Главная, Модели, Спецификации, Заказы и «Ещё» на мобильном; на desktop оставить тёмный рельс без снабженческих разделов в основной навигации.
- Создать переиспользуемый `BatchCard` для активных партий: миниатюра модели, номер формата `ПР-2026-…`, модель, спецификация, цех, статус, срок, количество и компактная разбивка по цветам.
- Сделать двухсоставные размерные элементы `размер | количество`, оптимизированные для быстрого чтения на 390px.
- Реализовать адаптивное раскрытие раскладки: 1–2 цвета открываются внутри карточки, 3+ цветов — в bottom sheet с затемнением и закрытием по фону/Escape.
- Обновить Главную как production-first экран: крупные фактические показатели, внимание, активные партии, последние спецификации и быстрые действия.
- Обновить сетку моделей: визуальная миниатюра, название, артикул, статус и производственная активность.
- Добавить экран модели с шапкой, пятью показателями и вкладками «Производство / Паспорт / Материалы / История», где производство открыто по умолчанию.
- Сохранить существующий паспорт партии, состояния интерфейса и локальную интерактивность; backend, API, БД и авторизацию не добавлять.

## Данные и ограничения

- Использовать только локальные mock-данные, необходимые для демонстрации запрошенной цепочки «Модель → Спецификация → Партия → Цвет → Размер → Количество».
- Не показывать UUID и служебные идентификаторы.
- Не использовать слово «BOM»; заменить его на «Спецификация» или «Нормы расхода материалов».
- Не копировать названия, номера, цвета и компоновку Octopus; изображения служат только ориентиром плотности и информационной иерархии.
- Визуальная система остаётся GarmentOS: тёплая нейтральная база, терракотовый акцент, Onest + IBM Plex Mono, мягкие тени, тонкие границы, радиусы 10–16px.

## Технические детали

- Расширить локальную типизацию моделей и партий данными спецификации, цвето-размерной раскладки и активности.
- Вынести новые повторяемые элементы в существующие frontend-компоненты, не дублируя desktop/mobile реализации.
- Использовать текущий `Drawer` как responsive bottom sheet, текущие animation/focus/design tokens и inline SVG-иконки.
- Проверить интерактивность и отсутствие горизонтального скролла на 390px, затем responsive-представление на desktop.
